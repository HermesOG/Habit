# Хранитель — логика приложения (handoff для Claude Code)

Telegram Web App: трекер задач / привычек / целей с геймификацией. У пользователя есть
персонаж-«Хранитель огня», который растёт по уровням от начисляемого XP («искры»). Весь UI —
единый Design Component (`Хранитель - Telegram App v4.dc.html`), а вся математика вынесена в три
чистых JS-движка. Ниже — полное описание того, как всё работает, чтобы можно было переписать на
реальном стеке (React + бекенд) без чтения исходного DC.

---

## 1. Архитектура файлов

- `xp-engine.js` → `window.GuardianXP` — чистая математика XP/уровней/дневного капа. Без состояния.
- `character-config.js` → `window.GuardianCharConfig` — ассеты персонажа, якоря (anchors), маппинг
  уровень→форма, набор визуальных эффектов по уровню.
- `sfx-engine.js` → `window.GuardianSfx` — синтез звука на Web Audio (никаких файлов).
- `CharacterStage.dc.html` — рендер персонажа: берёт PNG формы по теме + накладывает эффекты по
  якорям (глаза, пламя, свечи, искры, трещина, нимб). Props: `level`, `theme`, `size`, `burst`
  (тик вспышки), `still`, `play-ceremony`, `anchors-override`.
- `Хранитель - Telegram App v4.dc.html` — весь UI и состояние (класс `Component`).
- `ios-frame.jsx` — только бутафорский корпус iPhone для превью; в проде не нужен.

## 2. Модель данных (источник истины)

Всё хранится в state компонента. В проде это таблицы/документы на бекенде + локальный кеш.

### Цель (goal)
```
{ id, name, hue (0–360, цвет цели), deadline: 'YYYY-MM-DD',
  steps: [ { id, name, date:'YYYY-MM-DD', done:bool, difficulty:1..5 } ] }
```

### Одиночная задача (solo task)
```
{ id, name, date:'YYYY-MM-DD', done:bool, difficulty:1..5 }
```

### Привычка (habit)
```
{ id, name, streak:int, doneToday:bool,
  schedule:'Ежедневно' | 'Пн · Ср · Пт' | ...,
  context:string (напр. «по утрам»), difficulty:1..5 }
```

### Герой + XP
```
hero: { name, level }         // level дублируется, но истина — xp.total (см. ниже)
xp: {
  total,          // суммарный XP — ЕДИНСТВЕННЫЙ источник истины для уровня
  day:'YYYY-MM-DD',
  dailyRaw,       // «сырой» XP, набранный за текущий календарный день (для дневного жара)
  log: { [itemId]: {gain, raw} },  // сколько реально начислено за пункт — для честного отката
  maxLevel        // максимально достигнутый уровень (чтобы церемонии level-up не повторялись)
}
xpDays: { 'YYYY-MM-DD': rawXpЗаДень }  // история дневного жара для теплокарты в календаре
```

### Настройки
```
settings: { sounds, haptics, starfield, monday(неделя с пн) }  // все bool
notif:    { push, tasks, habits, achievements, weekly }         // все bool
theme:    'amber' | 'azure' | 'spark'  (в localStorage 'guardian-theme')
```

## 3. XP-движок (`GuardianXP`, xp-engine.js)

Все функции чистые, без состояния.

**Базовый XP по сложности (1–5):**
- Задачи: `[5, 10, 20, 35, 55]` → `taskXp(diff)`
- Привычки (база): `[4, 8, 15, 25, 40]` → `habitBase(diff)`

**Стрик-множитель привычек** (`streakMult(streak)`):
- `<7` → ×1.0; `≥7` → ×1.25; `≥30` → ×1.5; `≥100` → ×2.0
- Итоговый XP привычки: `habitXp(diff, streak) = round(habitBase(diff) * streakMult(streak))`

**Дневной жар (мягкий кап)** — `applyCap(rawBefore, amount)`:
- `DAILY_CAP = 150`, `OVERFLOW_RATE = 0.3`.
- Первые 150 «сырых» XP за календарный день начисляются полностью; всё сверх — ×0.3.
- Возвращает `{ granted (округл. итог), rawAfter (rawBefore+amount), capJustHit (bool) }`.
- `capJustHit` = true в момент пересечения порога → показать тост «предел дневного жара» + звук `cap`.

**Кривая уровней:**
- Стоимость перехода n→n+1: `need(n) = round(10 * n^1.2 / 5) * 5`.
- `levelFromXp(total)` → `{ level, into (XP внутри уровня), need (до следующего), progress 0..1 }`.
- Уровень выводится из `xp.total` — никогда не хранить level отдельно как истину.

## 4. Начисление и откат XP (логика в DC)

**`_grantXp(id, amount, opts)`** (упрощённо):
1. Определить «сырой до» = `xp.dailyRaw`, если `xp.day === сегодня`, иначе 0 (новый день обнуляет жар).
2. `res = GuardianXP.applyCap(rawBefore, amount)`.
3. `total = xp.total + res.granted`; пересчитать `lvNew` vs `lvOld` из total.
4. Обновить `xp`: `total`, `day=сегодня`, `dailyRaw=res.rawAfter`, `maxLevel=max(...)`,
   и `log[id] = {gain: res.granted, raw: amount}` (если не `opts.noLog`).
5. Если `lvNew > lvOld` и `lvNew > предыдущего maxLevel` → запустить церемонию level-up
   (`pendingLevel/leveled`) и звук `levelup`. Иначе обычная «искра» (`_spark`) + звук `complete/habit`.
6. Если `res.capJustHit` → тост «дневной жар» + звук `cap`.

**Откат (undo)** — при снятии галочки/отмене: берём `xp.log[id].gain` и вычитаем именно столько,
сколько реально было начислено (не пересчитывая по формуле — иначе кап сломает баланс).
Удаляем запись из `log`, корректируем `dailyRaw`, звук `undo`.

**Ключевые правила:**
- Уровень всегда `levelFromXp(xp.total).level`. Прогресс-бар героя = `.progress`.
- Церемонии повышения уровня не повторяются (сравнение с `xp.maxLevel`).
- Дневной жар и `xpDays[дата]` питают теплокарту календаря.

## 5. Персонаж (`GuardianCharConfig`, character-config.js)

**Формы по уровню** — `formFor(level)`:
- `1` (lvl 1–9), `2` (10–19), `3` (20–39), `4` (40–49), `5` (50+).

**Титулы** (`TITLES`): 1 Тлеющий, 5 Зажжённый, 10 Окрепший, 20 Яркий, 29 «???», 40 Пылающий, 50 Хранитель.

**Ассеты** (`ASSETS[theme].formN`) — PNG в `uploads/` для тем amber/azure/spark, формы 1–5.

**Якоря** (`ANCHORS[theme].formN`) — координаты в % контейнера (`{x,y}`), куда CharacterStage кладёт
эффекты: `peakL/peakR` (кончики капюшона), `eyeL/eyeR`, `scarfKnot`, `notch`, `hemCenter`,
`crownCenter`. У каждой темы своя таблица; пользовательские правки кладутся поверх дефолтов в
localStorage (`gsAnchors.v1`) через `saveAnchors/resetAnchors`. Экран «Калибровка» (dev-флаг
`DEV_CALIBRATION`) позволяет таскать якоря мышью и экспортировать JSON.

**Метрики** (`METRICS.formN`) — размеры/разброс глаз, пламени, свечей для каждой формы.

**Эффекты по уровню** — `visuals(level)` возвращает флаги, которые CharacterStage применяет:
- `eyesDim` (<5) — приглушённые глаза; `smoke` (<5) — дымки с пиков.
- `candles` (5–9) — SVG-свечи на кончиках капюшона.
- `flameFlicker` (form≥2), `eyePulse` (≥5) — идл-анимации.
- `lining` — яркость подкладки: 0 / 0.3 (≥20) / 0.6 (≥40) / 0.95 (≥50).
- `sparks` — число искр: 0 / 3 (≥20) / 5 (≥29) / 6 (≥40) / 9 (≥50).
- `crack` + `slivers` (ровно lvl 29) — «аномалия»: пульсирующая трещина + язычки над глазами.
- `residual` (30–39) — остаточное свечение (память о трещине).
- `halo` + `crown` (≥50) — нимб и корона у финальной формы.

Уровень 29 — сюжетная «аномалия»: экран «Путь» показывает её отдельно, тап по ней даёт тост.

## 6. Звук (`GuardianSfx`, sfx-engine.js)

Полностью синтезированный Web Audio (реверб + компрессор/лимитер, инhармонические колокола,
шумовые «угольки», ризеры, шиммер, лейтмотив-триада). Тембр следует теме (`setTheme`).

API: `setEnabled(bool)`, `isEnabled()`, `setTheme('amber'|'azure'|'spark')`, `unlock()` (по первому
жесту), `play(name, arg)`.

Cue-и: `complete(diff 1..5)` (с комбо-подъёмом серии), `habit(streak)`, `streak()`, `goal()`,
`levelup()`, `undo()`, `cap()`, `tap()`, `open()`, `toggle(on)`, `error()`.

В DC любой звук идёт через `_sfx(name, arg)`, который проверяет `settings.sounds`.

## 7. Темы

Три темы — объекты в `_themes()`: `{ id, name, caption, bg, surface, surface2, accent, deep, tp
(text primary), ts (text secondary), cloak }`. Применяются как CSS-переменные через `_varsOf(t)`
(`--bg`, `--surface`, `--accent`, …). Выбор темы: экран «Внешний вид» → предпросмотр на карточках →
кнопка «Применить» (`applyTheme`): короткий crossfade-флаг `theming`, запись в localStorage, смена
темы у SFX, тост «Тема применена». Персонаж перерисовывается под новую тему (свой набор PNG+якорей).

## 8. Экраны (state.screen)

`home` (Сегодня: герой+прогресс, задачи/привычки на сегодня), `tasks` (Все задачи: цели со
ступенями + одиночные), `calendar` (месяц с теплокартой дневного жара, выбор дня), `account`
(Профиль), `appearance` (выбор темы), `settings`, `notifications`, `help` (FAQ-аккордеон),
`about`, `path` (лестница форм/уровней + аномалия 29), `calibration` (dev: подгонка якорей).

Навигация — `go(screen)`; нижний таб-бар + кнопка «+» (`openCreate`) с выбором типа
(задача/привычка/цель) и черновиком `draft`.

**Утилиты дат** (жёстко зашита «сегодня» = 2026-06-12 для демо — в проде взять реальную дату):
`_today`, `_d`, `_diff`, `_overdue`, `_left`, `_fmt`, `_wd`, `_pl` (склонение),
`_triage(date)` → цвет/подпись по просрочке (сегодня / просрочено на N дней).

**Цвета целей от hue:** `_gcolor(hue, daysLeft)`, `_vivid`, `_dot`, `_tint` — все на oklch,
насыщенность растёт по мере приближения дедлайна.

## 9. Что вынести на бекенд при переписывании

- CRUD задач/привычек/целей+ступеней; отметка выполнения → начисление XP через `GuardianXP`.
- Хранение `xp` (total/day/dailyRaw/log/maxLevel) и `xpDays` — эту логику капа/уровней держать
  серверной, чтобы нельзя было накрутить. Клиент показывает, сервер считает.
- Сброс дневного жара по календарной дате пользователя (таймзона!).
- Стрики привычек: инкремент при выполнении в срок, обнуление при пропуске по расписанию.
- Настройки/тема — профиль пользователя; тема также в локальном кеше для мгновенного старта.
- Движки `xp-engine.js` / `character-config.js` — переиспользуемы как есть (чистый JS, без DOM).
  `sfx-engine.js` — только клиент.

## 10. Точные константы (не терять при переносе)

- TASK_XP `[5,10,20,35,55]`, HABIT_XP `[4,8,15,25,40]`, DAILY_CAP `150`, OVERFLOW_RATE `0.3`.
- streakMult пороги 7/30/100 → 1.25/1.5/2.0.
- need(n): уровни 1–9 — `[10,15,20,25,30,40,45,50,55]`; n ≥ 10 — `round(8 * n^1.2 / 5) * 5`
  (с сентября 2026; прежняя `round(10 * n^1.2 / 5) * 5` давала вторую форму лишь на 15-й день).
  `totalFor(lvl)` — суммарный XP до уровня, для прогноза на экране «Путь».
- Границы форм: 10 / 20 / 40 / 50. Аномалия — ровно уровень 29.

## 12. Онбординг (сентябрь 2026)

Показывается один раз тем, у кого после загрузки хранилища нет ни привычек, ни задач, ни целей
(`_applyLoaded`: первый запуск или пустое состояние). У кого данные есть — флаг `onbDone`
выставляется молча. Флаг хранится в слайсе (`_persistSlice`), само состояние `onb` — нет: закрыл
приложение на полпути → при следующем запуске онбординг либо повторится (ничего не создано),
либо не покажется (привычка с шага 2 уже есть). «Пропустить» доступен на любом шаге.

Шаги (`onb.step`), оверлей z-index 40 под церемонией уровня (45):
1. знакомство: Хранитель формы 1 с потушенными глазами, имя (по умолчанию из языка), выбор языка;
2. одна привычка: шесть карточек `STARTERS` (тексты `starterNames`) или своя, «когда» (утром/днём/вечером →
   `context`); по «Дальше» привычка создаётся (`habit_created`, `first_habit`);
3. что дальше: превью уровней 2 / 5 / 10 (эффекты `eyesDim` снимаются со 2-го, свечи с 5-го, форма 2 с 10-го);
4. первая искра: «сегодня уже сделал(а)?» — «да» → `toggleHabit` → +8 XP → уровень 2 (`need(1) = 8`)
   и церемония «Хранитель открыл глаза» (`awake`); «ещё нет» → час вечернего напоминания (17–23) → `/api/prefs`.

События воронки: `onb_1`, `onb_2`, `onb_3`, `onb_done`/`onb_skip` (meta.step), `first_check_same_session`.

## 11. Сервер (сентябрь 2026)

Приложение по-прежнему хранит всё у пользователя. На сервер уходят только:
- `hit` при запуске (визит, источник, бонус за друзей), `act` при отметке (день действия + сводка
  привычек для текста напоминания), `event` (события воронки), `prefs` (настройки напоминаний),
  `share` (карточка «Поделиться»). Все — с подписанным `initData`; вне Telegram не вызываются.
- Сводка `_summary()`: `{v, lvl, t (задач на сегодня), h:[{n, s, d, sch, days}]}` — без содержания
  задач и целей. Уходит из `_actionPing` и, при изменении, из `_flush` не чаще раза в минуту.
- Бонус за друга: `hit` отдаёт `bonus` → `_applyBonus()` начисляет после загрузки состояния и
  подтверждает событием `bonus_claimed` (сервер списывает `pending_bonus`).
